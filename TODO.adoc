== What bugs are present

* `@forastro/utilities` publishes a broken package. Its generated exports reference a missing type declaration and a missing components entry point; the tarball contains only `index.js`, `index.d.ts`, and `package.json`.
* The AsciiDoc loader uses `astroConfig.root.pathname` as a filesystem path. On Windows this becomes `/C:/...`, causing `fast-glob` to find no content. Use `fileURLToPath(astroConfig.root)` and platform-safe path operations.
* `apps/mock-blog/src/content.config.ts` passes `src/content/blog` even though the loader appends the collection name, producing `src/content/blog/blog`.
* The AsciiDoc watcher `add` handler reverses the `projectRelativePath` and `slug` arguments passed to `setStoreUsingExtractedInfo`.
* Loader entries are keyed only by filename, so equal filenames in different directories collide. Loader configuration is also cached in mutable module-global state and can leak between loader instances.
* The Nx page generator emits obsolete Astro content APIs: `entry.slug` and `entry.render()`. It also generates incorrect fixed `../layouts` imports for nested pages.
* The collection-schema generator writes legacy per-collection `src/content/<collection>/config.ts` files instead of updating `src/content.config.ts` for Astro 7.
* AsciiDoc support detection does not recognize `@forastro/asciidoc`, and generated AsciiDoc content does not satisfy `asciidocBaseSchema`.
* The app and add-integration generators execute external commands directly instead of deferring side effects through Nx tasks. They can mutate disk during a dry run, and the current Tree may not see the generated files.
* Generator options including `typescript`, `integrations`, `eslint`, `skipInstall`, and `packageManager` are exposed but ignored. Executor options including build/preview `outDir` and dev `root` are also ignored.
* The root `ci` script lacks command separators. The AsciiDoc and utilities `check` targets are no-ops, CI omits the real `type-check` targets, and affected commands can select nothing after a push to `main`.
* The release workflow can run for both a merged pull request and its push to `main`, risking duplicate release attempts.
* Template dependencies use unrestricted `*` ranges. Their `@forastro/utilities` dependency resolves to registry version 5.1.3 instead of workspace version 7.0.1, so template builds do not test current code.
* `pnpm audit --prod` reports 27 vulnerabilities: 1 critical, 19 high, 6 moderate, and 1 low. Important paths include Handlebars through Asciidoctor, direct old Sharp versions, Preact, and `smol-toml` through Nx.
* `nx.json` contains a committed read-write Nx Cloud token that must be rotated and moved to CI secrets.
* Builds still report empty blog collections, a missing Astro Icon source directory, an implicit-any hint, and deprecated UnoCSS `presetWind` usage.
* README package versions and build instructions are stale, and `TRIAGE.md` describes obsolete failures and nonexistent files.
